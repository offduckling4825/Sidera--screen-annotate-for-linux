# 重构计划

更新：2026-10-24；分支 `custom`。按当前实现重新排期，旧阶段进度保留在 Git 与 [历次记录](audit/README.md) 中。问题编号见 [ISSUES.md](ISSUES.md)。

## 已完成的基础工作

- Rust 分离 Desktop、多屏状态、页缓存、原子保存、实例锁及 HTTP 解析；保留现有绘图和课堂界面。
- C++ 两条后端共用 WpsBridge、安装登记脚本和压缩页缓存。
- 补齐白板外部状态跟踪、乱序请求保护、缓存超页数保留和缓冲生命周期。
- 增加隔离执行入口、私有 Xvfb/Sway 检查、C++ 内存错误检测、实际 ELF 依赖生成。
- 工具链、后端构建开关、custom CI 触发及文档现状已更新。

这些是实现及隔离检查进度。桌面验收、ARM64 和低 ABI 发布仍按下列门禁推进，不做“全部兼容”的结论。

## 必须保持的行为

| 范围 | 不变量 |
| --- | --- |
| 绘图 | 模式切换不破坏既有笔迹；撤回使用匹配 DPI 的像素区域 |
| 页缓存 | 有笔迹的页不能因到达固定页数静默丢弃；清空页不能恢复旧快照 |
| 白板 | 关闭后保留；外部放映变化不改白板内容；退出恢复最新透明页 |
| 工具栏 | 保持现有位置与触摸反馈；整条手动收起不能被绘图组状态自动打开 |
| WPS | 真换页才切换批注；API 已接受时不再补发键盘造成双翻页 |
| 显示 | busy 缓冲不改写；尺寸、存储和输入区匹配；输出变化不误用旧坐标 |
| IO | 原子写入；失败可观察；测试不修改真实用户配置 |

## 下一阶段

### 1. 完整放映会话协议（S07、S09、S10、S12）

当前 sid/seq 解决单请求流倒序，不解决多客户端竞争和命令执行确认。先用隔离 fixture 明确以下转换，再在兼容现有 WPS 的前提下实施：

- 加载项实例、活动文稿、一次放映会话分别标识；旧文档的延迟消息不能覆盖新文档。
- 命令携带唯一编号、截止时间和执行结果，断线后不重复执行。
- 认证通过受控握手建立，不把长期密钥放在公开 JS；实际 WPS 的 Origin/请求能力先验证。
- 保留旧 GET 协议适配，分别覆盖新旧主程序与加载项组合；旧客户端不获得不存在的顺序保证。

退出条件：双客户端切换、同页重连、桥重启、旧会话晚到、命令超时、白板中结束再开始均有一致的状态断言；再由用户验收真实课件。

### 2. 平台功能收尾（S16–S21）

Rust 优先完成 GNOME 原生和学校实际 X11 环境的人工矩阵。多输出、混合 DPI、投影仪热插拔、截图粘贴、锁屏恢复及物理触屏分别记录，不以一个鼠标场景代替全部功能。

C++ 继续明确为旧实现：Wayland 单输出、无 GNOME 扩展、缺少完整掌擦与原生剪贴板。若继续补齐，先共用输入/页面状态，再增加能力；不能借用 Rust 的测试结论宣称功能一致。

退出条件：每个声明支持的桌面都有对应版本、设备、场景和结果；不支持项与界面能力反馈一致。

### 3. 资源与结构（S24–S26）

每份页缓存已有压缩预算，但多个屏幕、撤回与临时编解码仍影响总内存。用 1080p/4K、50 页、双屏和长课记录峰值 RSS、页切换耗时及输入延迟，再决定全局预算、异步压缩或增量存储，避免凭猜测更换渲染方式。

接着将 Rust main 的放映转换、动作调度从 UI 路由分离；C++ 逐步将全局 g 的页面和输入所有权明确化。两种语言共享行为 fixture，暂不引入跨语言 FFI 或替换前端。

退出条件：抽取前后行为检查相同；性能结论带硬件、负载和测量方法；低内存/磁盘写入失败不静默丢页。

### 4. 可复现发布（S14、S22、S23、S27、S28）

- 提供固定来源、版本与校验和的 rootfs 初始化步骤；记录编译器、库版本、能力、源提交和二进制哈希。
- 在学校 ARM64/glibc 2.31 和 Ubuntu 24.04 对应环境独立构建、安装、升级、重装和卸载。
- 发布门禁检查 ELF/control 架构及动态依赖，明确资源/desktop、图标缓存、自启动和权限规则。
- 对任务栏本来不显示的覆盖层注明不适用；应用菜单、收藏及程序内图标分别验收。
- 许可声明保留上游原文，元数据差异由权利人明确后再处理，不自行改成 MIT。

退出条件：每个发布包都能追溯到实际构建输入和测试记录；没有目标环境结果时保持预发布并写明限制。

## 执行方式

一次只推进一个有明确行为边界的改动，先保存可复现证据，再修改、复查、执行适当检查。已有通过项只在相关代码变化或发现新风险时重跑；不因计划覆盖面大而一次改写全部状态机。

当前用户授权隔离代码及协议检查，真实 VMware 桌面和 WPS 仍由用户测试。当前命令和矩阵见 [TEST_ENVIRONMENT.md](TEST_ENVIRONMENT.md)。
